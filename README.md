# Sonic Share

Sonic Share передаёт файлы и текстовые сообщения между устройствами с помощью
звука. Для работы не нужны Wi-Fi, Bluetooth, мобильный интернет или сервер: одно
устройство воспроизводит закодированный аудиосигнал, а другое принимает его через
микрофон.

Репозиторий содержит переиспользуемый акустический модем на Rust, терминальный
клиент и мобильное приложение на Flutter. Общее ядро отвечает за коррекцию
ошибок, сжатие, метаданные передачи и проверку целостности данных.

## Возможности

- Передача файлов через динамик и микрофон.
- Обмен короткими текстовыми сообщениями в режиме чата.
- Терминальный интерфейс с режимами отправки, приёма и чата.
- Flutter-клиент, использующий общее нативное ядро на Rust.
- Коррекция ошибок Reed-Solomon и проверка целостности по SHA-256.
- Запись WAV и офлайн-декодирование для диагностики.

## Структура репозитория

| Путь | Описание |
| --- | --- |
| `core/` | Акустический кодер и декодер, детектор сигнала, FEC и протокол передачи. |
| `cli/` | Терминальный клиент на Rust и диагностические утилиты. |
| `mobile/` | Flutter-приложение для Android и iOS. |
| `mobile/rust/` | Адаптер Flutter Rust Bridge для `core`. |
| `mobile/rust_builder/` | Интеграция сборки нативного Flutter-плагина. |

## Требования

- Rust и Cargo.
- Рабочие микрофон и устройство вывода звука для CLI.
- Flutter SDK с поддержкой Dart `^3.12.2` для мобильного приложения.
- Android Studio и Android SDK либо Xcode и CocoaPods для целевой платформы.

Проверить установленные инструменты можно командами:

```bash
rustc --version
cargo --version
flutter doctor
```

## Терминальный клиент

Запустите терминальный интерфейс из корня репозитория:

```bash
cargo run -p sonic-share-cli
```

Интерфейс состоит из трёх вкладок: Send, Receive и Chat. Принятые файлы
сохраняются в каталог `received/`, а история сообщений хранится в памяти только
до завершения программы.

| Клавиша | Действие |
| --- | --- |
| `1`, `2`, `3` или `Tab` | Переключить режим. |
| `Enter` | Отправить путь или сообщение либо запустить/остановить приём. |
| `Esc` | Выйти из режима ввода; повторное нажатие завершает программу. |
| `q` | Завершить программу вне режима ввода. |
| `r` | Запустить или остановить приём в режиме Chat. |

Диагностические утилиты можно запускать отдельно:

```bash
# Отправить файл
cargo run -p sonic-share-cli --bin send -- file ./example.bin

# Отправить сообщение
cargo run -p sonic-share-cli --bin send -- text "Привет" --content-type text/x-sonic-chat

# Принимать данные в указанный каталог
cargo run -p sonic-share-cli --bin listen -- --output-dir received

# Записать 10 секунд звука с микрофона
cargo run -p sonic-share-cli --bin record -- recording.wav 10

# Декодировать ранее записанный сигнал
cargo run -p sonic-share-cli --bin decode -- recording.wav

# Быстро проверить все тестовые assets и сравнить airtime профилей
cargo run -p sonic-share-cli --bin bench-assets -- assets
```

По умолчанию используется надёжный hybrid-профиль OFDM (дифференциальный DBPSK с
частотным разнесением rep-2 и FSK-манифестом), проверенный на реальном тракте
динамик→микрофон MacBook с побайтовой SHA-256 сверкой. Флаг `--qam16` включает
более быстрый OFDM (дифференциальный QPSK) для чистого канала, `--fsk` — старый
Fast FSK, а `--robust` — Robust FSK для максимальной дистанции и высокого шума.
Несколько пар в одном помещении должны использовать разные частотные полосы,
например `--lane 0` и `--lane 1`; одинаковый lane у одновременных передатчиков
приведёт к коллизии.

## Мобильное приложение

Установите зависимости и запустите Flutter-клиент:

```bash
cd mobile
flutter pub get
flutter run
```

Сборка приложений выполняется из каталога `mobile/`:

```bash
flutter build apk --debug
flutter build ios --debug --no-codesign
```

Для приёма данных приложению нужен доступ к микрофону. Во время тестирования
расположите устройства рядом и установите достаточную громкость на передающем
устройстве.

## Разработка

Перед отправкой изменений запустите проверки Rust и Flutter:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets
cargo test --workspace

cd mobile
flutter analyze
flutter test
```

Файлы `Cargo.lock`, `pubspec.lock` и lock-файлы CocoaPods намеренно хранятся в
репозитории, чтобы сборки приложений оставались воспроизводимыми.

## Ограничения

Скорость и надёжность акустической передачи зависят от качества динамика,
чувствительности микрофона, фонового шума, эха и расстояния между устройствами.
Начинайте тестирование с небольших файлов, не используйте максимальную громкость
при появлении искажений и по возможности проводите передачу в тихом помещении.
