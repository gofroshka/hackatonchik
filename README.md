# Акустический модем (data-over-sound)

Мобильное Flutter-приложение для передачи цифровых данных между двумя
смартфонами **через звук** — без интернета, Bluetooth, Wi-Fi и NFC. Один
телефон кодирует текст в аудиосигнал и проигрывает его через динамик, второй
записывает звук микрофоном, распознаёт сигнал и восстанавливает исходный текст.

---

## Что делает приложение

- Кодирует произвольный UTF-8 текст (латиница, кириллица, emoji) в звук.
- Передаёт его акустически по протоколу **BFSK** (Binary Frequency-Shift Keying).
- Принимает звук микрофоном, демодулирует и собирает исходное сообщение.
- Делит длинные сообщения на пакеты и собирает их обратно.
- Проверяет целостность каждого пакета через **CRC16** — сообщение
  показывается пользователю только после успешной проверки.
- Имеет полноценную диагностику DSP и Demo Mode, работающий на одном устройстве.

---

## Архитектура

Проект разделён на чистые (не зависящие от Flutter) DSP/протокол-модули и слой
UI. Вся тяжёлая обработка сигнала вынесена в отдельный **Isolate**.

```
lib/
  app/            # MaterialApp, тема, Riverpod-провайдеры
  audio/          # запись/воспроизведение PCM, конвертация
    audio_input.dart      # микрофон -> поток нормализованных сэмплов (record)
    audio_output.dart     # воспроизведение PCM (flutter_pcm_sound)
    pcm_converter.dart     # int16 <-> float <-> bytes
  modem/          # DSP-ядро модема
    modem_config.dart      # ВСЕ параметры в одном классе
    goertzel.dart          # энергия на частоте (алгоритм Гёрцеля)
    bfsk_modulator.dart    # биты -> BFSK PCM (непрерывная фаза)
    bfsk_demodulator.dart  # PCM -> биты + confidence
    synchronizer.dart      # поиск преамбулы и точного смещения символа
    signal_detector.dart   # adaptive noise floor + SNR
    ring_buffer.dart       # кольцевой буфер сэмплов
    streaming_decoder.dart # конечный автомат приёма в реальном времени
    acoustic_modem.dart    # фасад: текст <-> PCM (offline)
  protocol/       # формат пакета и коррекция ошибок
    crc16.dart             # CRC16-CCITT
    repetition_code.dart   # повторение ×3 + majority voting
    packet.dart / packet_encoder.dart / packet_decoder.dart
    packet_fragmenter.dart # длинное сообщение -> пакеты
    message_assembler.dart # пакеты -> сообщение
  workers/        # изоляты
    decoder_worker.dart    # StreamingDecoder в отдельном Isolate
    decoder_messages.dart
  features/       # экраны
    send/ receive/ diagnostics/ demo/
  shared/         # утилиты и виджеты (WAV, биты, график энергии)

test/
  protocol/  modem/  integration/   # 38 тестов
```

**Управление состоянием:** Riverpod (`ChangeNotifierProvider`), последовательно
во всех экранах. DI — через провайдеры, без тяжёлых фреймворков.

**Поток данных при передаче:**

```
String → UTF-8 → пакет(ы) → CRC16 → повторение ×3 → биты
       → BFSK PCM (24 кГц, int16 LE) → динамик
```

**Поток данных при приёме (в изоляте):**

```
микрофон → PCM → ring buffer → детектор сигнала → поиск преамбулы
        → синхронизация символа → BFSK-демодуляция (Гёрцель)
        → majority voting → парсинг пакета → проверка CRC
        → сборка сообщения → UI
```

## Используемая модуляция

**BFSK** — два тона кодируют логические `0` и `1`. Передатчик использует
**continuous-phase FSK со сглаженным (raised-cosine) переходом частоты** на
границах символов (GFSK-подобно): непрерывны и фаза, и мгновенная частота,
поэтому в сигнале **нет широкополосных щелчков**. Это важно вдвойне: клики
неприятны на слух и, главное, их **срезает шумодав телефона**, ломая передачу.

На стороне приёмника энергия каждого тона измеряется алгоритмом **Гёрцеля**
(дешевле полного FFT — нужны лишь две частоты) по **центральной части символа**
(переходные края пропускаются). Решение о бите — по тому, какая частота
мощнее; `confidence = |E1 − E0| / (E1 + E0)`.

### Борьба с обработкой звука телефоном

Чтобы встроенные шумоподавление/AGC/эхоподавление не искажали тоны, запись
ведётся из «сырого» источника **`AndroidAudioSource.unprocessed`** (fallback →
`mic` → `default`), с выключенными `autoGain`, `echoCancel`, `noiseSuppress` и
режимом `modeNormal`. На входе приёмника дополнительно стоит полосовой фильтр
1100–2900 Гц.

### Надёжный разбор кадра по длине

После преамбулы приёмник читает заголовок, узнаёт длину payload и **дочитывает
ровно весь кадр по длине**, игнорируя кратковременные провалы энергии (клики,
AGC, шумодав) — вместо остановки на первом «тихом» символе.

### Параметры частот (по умолчанию, `ModemConfig`)

| Параметр            | Значение                    |
|---------------------|-----------------------------|
| Бит `0`             | 1500 Гц                     |
| Бит `1`             | 2500 Гц                     |
| Длительность символа| 40 мс (макс. надёжность)    |
| Переход частоты     | 3 мс raised-cosine (GFSK)   |
| Sample rate         | 48 000 Гц, mono             |
| Формат              | PCM signed 16-bit LE        |
| Амплитуда           | 0.7 (защита от clipping)    |
| Преамбула           | 64 бита `1010…`             |
| Полосовой фильтр (RX)| 1100–2900 Гц (биквады RBJ) |
| Коррекция ошибок    | повторение ×3 + majority    |
| Сырая скорость      | 25 бит/с                    |
| Полезная скорость   | ≈8.3 бит/с (после ×3)       |

Все параметры собраны в одном классе `lib/modem/modem_config.dart` и меняются в
одном месте. Ультразвук в базовом режиме не используется.

### Устойчивость к шуму

- Adaptive noise floor + порог по SNR перед началом декодирования.
- Синхронизация: перебор нескольких смещений окна вокруг предполагаемой границы
  символа, выбор варианта с максимальной суммарной энергией целевых частот
  (приёмник **не** предполагает, что запись началась ровно на границе символа).
- Soft-decision majority voting с учётом confidence каждого повтора бита.
- Плавные raised-cosine рампы на краях тонового пакета — нет щелчков и splatter.
- Непрерывная фаза между символами.

## Формат пакета

На линии (после преамбулы, до повторного кодирования):

```
| sync (2) | version (1) | type (1) | sequence (1) | length (2) |
| payload (0..128) | CRC16 (2) |
```

- **sync word:** `0xDDAA`
- **version:** `1`
- **CRC16:** считается по `version..payload` (CCITT-FALSE, poly `0x1021`,
  init `0xFFFF`).

Полезная нагрузка ограничена **128 байтами**. Внутри payload находится
фрагментный заголовок для сборки длинных сообщений:

```
| messageId (1) | packetIndex (1) | packetCount (1) | chunk (≤125) |
```

Длинные сообщения автоматически делятся на несколько пакетов и собираются
обратно `MessageAssembler` (поддерживается приход фрагментов не по порядку).

Физический кадр в эфире:

```
тишина → преамбула (64 бита 1010…) → sync+заголовок+payload+CRC (×3) → тишина
```

## Как запустить

Требуется установленный Flutter (проверено на Flutter 3.44 / Dart 3.12).

```bash
flutter pub get
flutter run           # на подключённом Android-устройстве
# либо собрать APK:
flutter build apk --debug
```

> ⏱️ **Первая сборка APK долгая (5–15 мин):** Gradle впервые компилирует
> нативную часть плагинов (record, flutter_pcm_sound, permission_handler,
> file_picker). Это одноразово — последующие сборки идут секунды. Это не
> зависание.

### Как выдать разрешение на микрофон

При первом запуске приёма Android покажет системный диалог — нажмите
**«Разрешить»**. Приложение обрабатывает все случаи и показывает понятные
сообщения:

- разрешение не выдано / отклонено / запрещено навсегда;
- микрофон занят другим приложением;
- устройство недоступно или не поддерживает запрошенный sample rate;
- уход в background.

Если доступ был запрещён навсегда — выдайте его вручную:
**Настройки → Приложения → Акустический модем → Разрешения → Микрофон**.

## Как проверить на одном устройстве

Не нужен второй телефон и даже микрофон:

1. Вкладка **Demo** → **«Loopback (без микрофона)»** — текст кодируется в PCM и
   тут же декодируется обратно; на экране появляется восстановленное сообщение.
2. **«Сохранить WAV»** — сгенерированный сигнал пишется в файл.
3. **«Открыть WAV и декодировать»** — выберите сохранённый WAV, он будет
   декодирован обратно в текст.
4. **«Воспроизвести сигнал»** — послушать, как звучит передача.

Также можно проверить «по воздуху» на одном столе: включите **Приём** на этом же
устройстве и дайте другому телефону/компьютеру проиграть WAV.

## Как проверить на двух устройствах

1. На **телефоне A** откройте вкладку **Приём** → «Начать приём».
2. На **телефоне B** откройте вкладку **Передача**, введите текст → «Передать».
3. Держите телефоны на расстоянии 10–40 см, динамиком B к микрофону A.
4. На A появится статус декодера (обнаружен сигнал → преамбула → пакет → CRC →
   сообщение принято) и восстановленный текст.

## Известные ограничения

- **Скорость низкая** (≈8 бит/с полезной нагрузки при символе 40 мс) — приоритет
  отдан надёжности, а не скорости. Короткая строка (`HELLO FROM AUDIO`)
  передаётся ~25–30 с; текст появляется после окончания передачи. Ускорить можно
  одним параметром `symbolDurationMs` в `ModemConfig`.
- Требуется относительно **тихое помещение**; сильный фоновый шум и реверберация
  снижают качество приёма.
- Громкая связь/динамик должны быть достаточно громкими; очень тихий звук ниже
  noise floor не декодируется.
- Одновременная передача с нескольких источников не поддерживается (один канал).
- iOS/desktop: DSP и WAV работают, но UX и разрешения оптимизированы под Android
  (основная платформа). На платформах без микрофона доступен Demo/loopback.
- Автоподстройка под другой sample rate микрофона выполняется приближённо
  (декодер использует конфиг; при импорте WAV — его собственный sample rate).

## Рекомендации для демонстрации

- Проверьте заранее: громкость B высокая (но не 100% — дешёвые динамики хрипят),
  микрофон A не закрыт чехлом.
- Расстояние 10–30 см, тихая комната, оба телефона на столе, неподвижно всю
  передачу (~25–30 с для короткой строки), дождитесь текста после тишины.
- Начинайте с короткой строки (`HELLO`), затем длинное сообщение и кириллицу.
- Держите открытой вкладку **Диагностика** на приёмнике — жюри видит энергии
  частот, SNR, confidence, найденный offset и статус CRC в реальном времени.
- Если приём «не ловит» — увеличьте громкость и сократите дистанцию.

### Сценарий презентации для жюри (2–3 минуты)

1. **(0:00–0:20) Проблема.** «Передача данных без сети, Bluetooth и NFC — только
   через звук. Полезно там, где радиоканалы запрещены или недоступны».
2. **(0:20–0:50) Demo на одном устройстве.** Вкладка **Demo** → «Loopback»:
   `HELLO FROM AUDIO` мгновенно проходит весь конвейер и декодируется. Показать
   число пакетов, бит и длительность сигнала. «Это доказывает, что модем
   математически корректен».
3. **(0:50–1:40) Передача между двумя телефонами.** Телефон A — «Приём», телефон
   B — «Передать `HELLO FROM AUDIO`». На A в реальном времени: обнаружен сигнал →
   преамбула → пакет → проверка CRC → **сообщение принято**. Текст на экране.
4. **(1:40–2:20) Надёжность.** Отправить кириллицу/emoji и длинное сообщение
   (разбивается на пакеты и собирается обратно). Показать вкладку
   **Диагностика**: энергии 1500/2500 Гц, SNR, confidence, CRC OK. Упомянуть,
   что повреждённый пакет отклоняется по CRC и не показывается.
5. **(2:20–3:00) Архитектура.** Чистые DSP-модули, DSP в отдельном Isolate (UI не
   блокируется), 38 автоматических тестов, WAV-экспорт/импорт. «Repetition-код
   легко заменить на Hamming/Reed–Solomon без изменения остальных слоёв».

## Способы дальнейшего улучшения

- Заменить повторение на **Hamming(7,4)** или **Reed–Solomon** (интерфейс
  `RepetitionCode` уже изолирован).
- Перейти на **MFSK/OFDM** или более короткий символ для роста скорости.
- Эквалайзер/адаптивный порог под характеристики конкретного динамика и комнаты.
- Ультразвуковой режим (>18 кГц) для «неслышимой» передачи.
- ACK/повторная передача потерянных пакетов (надёжный канал).
- Автоопределение sample rate и калибровочный тон перед сеансом.
